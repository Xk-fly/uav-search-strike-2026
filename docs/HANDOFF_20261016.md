## 2. 从零恢复正式比赛（仅已全部退出时）
```bash
# 终端一：PX4 / CopterSim / RflySim，先启动
cd ~/PX4PSP
./SITLRun.sh

# 终端二：ROS/感知/规划/行为树/大模型一键脚本，后启动
conda activate demo
export ROS_MASTER_URI=http://127.0.0.1:11311
cd ~/catkin_ws
bash ./sim_env_start.sh
```
`sim_env_start.sh` 启动 roscore、九格 `mission_once.py`、YOLO、`main.py` (内含 MAVROS 初始化)、场景、点云转换、ArUco、Ego、行为树等；**不启动 PX4 本身**。飞行中不可重跑；其 `kill_ros_pid.sh` 可能 killall python3。

开飞前集中检查：
```bash
export ROS_MASTER_URI=http://127.0.0.1:11311
rosnode list | grep -E '^/(mavros|ego_planner_node|aruco_detect_node|llm_mission_node)$'
rosservice list | grep '^/aruco/enable$'
timeout 6 rostopic echo -n 1 /mavros/state
rostopic info /objects
rostopic info /mission_command
```
确认 MAVROS connected/armed false，`/mission_command` 有 BT 订阅；不要因模型提示“已发送”而认为飞机必然执行。历史曾有 /llm_mission_node 没启动、/aruco/enable 缺失导致失败。

## 3. 主任务、关键机制
模型路径 `~/model/mission_once.py` + `~/model/FM9G4B-V`，提示词 `~/model/prompts/mission_prompt.txt`。在 LLM Xterm 输入官方根目录 `自然语言命令测试.md` 的红球中文命令后，应输出：
```command
takeoff
cross_frame
detect_aruco
return_cross_frame
hit_balloon:red
land
```
该多行文本直接发 `/mission_command`，行为树 `bt_ros.cpp` 转 XML 顺序执行。模型不是直接飞控；`GoTo` 是纯位置命令（不经 Ego），`PlanningControl` 才经 `/move_base_simple/goal`、`/planning/pos_cmd` 接 Ego 规划。

当前固定点：正向框观察点 `(0,-1,1)`，ArUco `(4.5,0.5,1.2)`，反穿准备 `(4.5,0.5,1.8)`，落地前 `(0,0,0.5)`。正向框中心估计来源为前视 YOLO 框尺寸+已知1.3m框尺寸的单目几何定位；ArUco 用下视相机解码 ID，不是在全场自主搜索标记。红球由颜色→预设区 A `(5.3,1.0,1.0)`、yaw≈π/2，再用前视像素 TargetTracker+VisualServo 跟踪；蓝→C、紫→B 配置不同。反穿复用首次 frame_center/planning_end_pos。当前 ArUco ID 还不会影响初始选球颜色。

## 4. 应优先解释/改进的现象
- **穿墙和超调**：GoTo 直航多处不经避障；且有限深度视场，不能保证 Ego 全局避障。详见 `docs/ISSUES_20261016.md`。
- **视觉盲区**：当前前视 sensor1 用于 YOLO，独立下视 sensor2 用于 ArUco；用户希望未来下视辅助气球发现，需标明相机源并校正外参，不可直接混像素。
- **任务结束判定**：气球 `ForceSuccess`/超时不能证明破裂；需仿真命中事件/得分与视频。
- **异常恢复**：任务 FAILURE 后可能悬停；`/mission_abort` 不意味着安全降落，切勿在飞行中强杀 ROS/Python。
- **其它未解**：深度空帧约一半、yaw:-nan 初始化、`cross_frame.launch` 嵌套替换报错、LLM 发布前无 schema 校验、YOLO clip 告警等。
